A) OTOMATIK WORKER OLCEKLEME (AUTOSCALE)
--------------------------------------------------------------------------------

Hat talebine gore desired_workers Postgres'te tutulur; actuator (noop / docker /
webhook) replica sayisini uygular.

HTTP load balancer YOK. Dagitim session_lease + claim_jobs affinity ile kalir.

FORMUL
------
  demand = aktif hatlar (enabled, kilitli degil,
           status: connected | connecting | qr_pending | pairing_pending)
         + lease'siz pending account.connect isleri

  desired = clamp( ceil(demand / capacity), MIN_WORKERS, MAX_WORKERS )

  capacity = SCALER_CAPACITY_PER_WORKER veya MAX_SESSIONS (varsayilan 50)

BILESENLER
----------
  wa.worker_heartbeat     Her worker boot + interval upsert
  wa.scaler_state         Tek satir: demand / desired / reason
  ROLE=scaler             Demand hesaplar, desired yazar, actuator cagirir
  admin_overview.scaler   demand -> desired, canli heartbeat (admin UI)

COMPOSE
-------
  # Solo worker ile cakismasin
  docker compose -f infra/docker-compose.yml stop wa-service

  # Scaler + scale edilebilir wa-worker (varsayilan actuator=noop)
  docker compose -f infra/docker-compose.yml --profile autoscale up -d --build

  # Desired'i elle uygulamak (noop sonrasi)
  docker compose -f infra/docker-compose.yml -p filo-wa --profile autoscale ^
    up -d --scale wa-worker=N wa-worker

  - wa-worker: container_name YOK; WORKER_ID=auto -> entrypoint worker-$hostname
  - wa-scaler: varsayilan SCALE_ACTUATOR=noop (imajda Docker CLI yok)
  - Gercek docker scale: host'ta ROLE=scaler veya docker-cli; Coolify: webhook
  - Scaler health: http://127.0.0.1:8090/health

ORTAM DEGISKENLERI
------------------
  ROLE                        worker | scaler (varsayilan: worker)
  SCALE_ACTUATOR              noop | docker | webhook (varsayilan: noop)
  SCALER_MIN_WORKERS          1
  SCALER_MAX_WORKERS          40  (20k icin yukseltin)
  SCALER_CAPACITY_PER_WORKER  MAX_SESSIONS (genelde 50)
  SCALER_INTERVAL_MS          20000
  SCALE_WEBHOOK_URL           webhook actuator URL
  HEARTBEAT_INTERVAL_MS       20000

  Pool kurali: desired * DB_POOL_MAX  <  Postgres/session pooler limiti

DOGRULAMA
---------
  1. SCALE_ACTUATOR=noop -> hat ekle -> wa.scaler_state.desired_workers artar
  2. Host'ta docker actuator -> desired 1->2 -> ikinci worker heartbeat
  3. Iki worker ayni hesabi acmaz (lease)

SINIRLAR
--------
  - Scaler RAM sihirbazi degil; MAX_WORKERS host kapasitesine gore set edilir
  - K8s HPA ileride ayni scaler_state.desired_workers okur
  - Org accounts_quota ayri; scaler TOPLAM demand'e bakar

Detay dosyalar: docs/autoscale.md , docs/scale-300.md , docs/saas-scale.md


--------------------------------------------------------------------------------
B) HARICI VT / PROJE — @wa/worker-kit
--------------------------------------------------------------------------------

Filo panel/admin AYNI KALIR. Bu paket yalnizca:

  1. Worker'in ihtiyac duydugu SQL demeti (sirali manifest)
  2. Job tipleri (@wa/shared re-export)
  3. Harici Postgres'e baglama talimati

Runtime process: apps/wa-service (Docker veya ROLE=worker|scaler)

MIMARI
------
  Harici_UI_veya_panel  --INSERT-->  public.jobs  <--claim--  wa-service
                                        |
                                     Postgres
                                        |
                                wa.* (creds, lease, ...)

  HTTP komut yolu YOK. Tek kanal: DATABASE_URL

HIZLI KURULUM (BOS / YENI SUPABASE)
-----------------------------------
  1) Sema demetini uret
     node packages/wa-worker-kit/scripts/verify-schema.mjs
     node packages/wa-worker-kit/scripts/bundle-sql.mjs
     -> packages/wa-worker-kit/dist/worker-schema.bundle.sql

  2) Uygula
     psql "%DATABASE_URL%" -f packages/wa-worker-kit/dist/worker-schema.bundle.sql

  3) Worker
     apps/wa-service/.env  ->  DATABASE_URL + WORKER_ID=...
     docker compose -f infra/docker-compose.yml up -d --build

     veya kit ornegi:
     docker compose -f packages/wa-worker-kit/docker-compose.example.yml up -d --build

  Filo tam urun (RLS, storage, admin) icin TUM supabase/migrations/ sirasini
  uygulayin. Kit panel katmanini bilerek disarida birakir.

MANIFEST
--------
  Dosya: packages/wa-worker-kit/schema/manifest.json

  - ~17 zorunlu migration (core + jobs + wa.* + affinity + heartbeat/scaler)
  - Panel-only dislanir: RLS, storage, realtime, admin_overview, ...

  Notlar:
  - brand_kits/creatives worker sorgulamaz ama FK zinciri icin zorunlu
  - organizations_tenancy org_id ekler — worker buna bagli
  - Autoscale tablolari demette (worker_heartbeat, scaler_state)

MINIMUM ENV
-----------
  DATABASE_URL   Session pooler, port 5432
  WORKER_ID      Process basina benzersiz
  ROLE           worker (varsayilan) veya scaler

  Ornek: apps/wa-service/.env.example

TIP SOZLESMESI (HARICI PANEL)
-----------------------------
  import { JOB_TYPES, type JobPayloadMap } from '@wa/worker-kit'

  Panel jobs INSERT ederken type + payload bu tiplerle uyumlu olmali.

SINIRLAR
--------
  - Kit Baileys kodunu cogaltmaz; servis monorepoda kalir
  - Saf Postgres (Supabase auth.users/roller yok) -> migration uyarlanmali
  - Kota/org politikasi host paneline aittir; worker toplam hesabi isler

Paket: packages/wa-worker-kit/README.md
Sozlesme: docs/worker-contract.md
